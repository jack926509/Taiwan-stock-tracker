## 軸 1：死碼

### 1-A【低】components/IndexBar.tsx（全檔 2 行）— 純死碼
- 證據：`components/IndexBar.tsx:1-2` 內容只有 `export { default } from "./IndexCard"`（向後相容再匯出）。全庫 grep `IndexBar`（app/components/lib）除本檔外零引用。
- 處置：直接刪除整檔。頁面用的是 `IndexCard`（`app/page.tsx:8` import `@/components/IndexCard`）。
- 風險：低（確定無引用）。

### 1-B【低】components/PWAServiceWorker.tsx（全檔 22 行）— 已定義但從未掛載
- 證據：`components/PWAServiceWorker.tsx:5` 是唯一定義，也是全庫唯一的 `navigator.serviceWorker.register("/sw.js")` 呼叫點（`:9-10`）。但 `app/layout.tsx:4-5` 只掛 `BottomNav`、`PWAInstallPrompt`，未 import 此元件；全庫無任何 import。
- 處置：刪除整檔。刪除不改變執行期行為（它本來就沒被掛載）。
- 附帶發現（非本次精簡造成）：既然此元件未掛載，目前 App 的 Service Worker 其實從未註冊 → PWA 離線功能實質未生效。若之後 UI 重設計仍要 PWA 離線，需重新把此元件掛進 layout 並確認 `/sw.js` 存在（原 sw.js 在被刪的 frontend/public/）。這是既有缺口，不是刪除帶來的。
- 風險：低（刪除本身無行為變化）。

### 軸 1 其餘：查過，無其他死碼
- lib/ 27 檔全部有 import（含 tests 引用），無孤兒模組。
- components/ 其餘 18 檔全部被 app/ 頁面 import（KlineChart 與 DraggableGrid 為 `next/dynamic` 動態載入，`app/stock/[id]/page.tsx:43`、`app/page.tsx:23`，非死碼）。

## 軸 2：重複邏輯

### 2-A【中】Quote 介面重複定義兩份（逐欄位完全相同）
- 證據：
  - `lib/types.ts:3-17` 定義 `Quote`（13 欄，前端用）。
  - `lib/providers/quoteProvider.ts:25-39` 定義 `Quote`（同 13 欄，後端用）。
  - 兩份欄位、型別、順序完全一致。前端側 5 檔用 types 版（`components/QuoteCard.tsx:4`、`IndexCard.tsx:3`、`app/alerts/page.tsx:7` 等）；後端側 3 檔用 provider 版（`lib/alerts.ts:5`、`alertLogic.ts:6`）。
- 處置：留一份為單一真相。建議 `quoteProvider.ts` 改成 `import type { Quote } from "@/lib/types"` 並 `export type { Quote }`（讓既有 `import { Quote } from ".../quoteProvider"` 不動）。注意 `alertLogic.ts` 是 type-only import（build 期抹除，`alertLogic.ts:2-3` 註解已說明 node --test 相容性），改動不影響測試。
- 風險：中（純型別，但跨前後端，須 `npm run build` 綠燈確認）。

### 2-B【低】跨日重判邏輯重複（1 行）
- 證據：`lib/alertLogic.ts:11` 的 `hitToday` 與 `lib/daily-summary.ts:72` 的判斷式完全相同：`taipeiNow(new Date(hitAt)).isoDate === taipeiNow(now).isoDate`。
- 處置：抽成 `market-hours.ts` 的共用 `isSameTaipeiDay(a, b)`，兩處呼叫。
- 風險：低（有 alertLogic 測試護欄；daily-summary 亦有測試）。

### 2-C【中】marketSession.ts 重造 Taipei 時間解析（市場已有 taipeiNow）
- 證據：`lib/marketSession.ts:19-37` 與 `:50-67` 兩次各自用 `Intl.DateTimeFormat` + 相同 `dowMap` 解析台北時間（同一段 code 在檔內重複兩遍）。而 `lib/market-hours.ts:69-91` 的 `taipeiNow()` 已回傳 `{ isoDate, minutes, dayOfWeek }`，正是這裡要的。
- 處置：`getMarketSessionLabel` / `getMarketSessionDetail` 改用 `taipeiNow(date)` 取 `minutes`、`dayOfWeek`，刪掉檔內兩段重複 Intl 解析（約省 30 行）。
- 風險：中（有 `tests/marketSession.test.mjs` 護欄，跑 `npm test` 該檔綠燈即可；但 marketSession 目前刻意零 import 保持純淨，引入 market-hours 依賴需確認 market-hours 無瀏覽器端不相容副作用——taipeiNow 為純函式，安全）。

### 軸 2 其餘：查過，以下「疑似重複」其實是刻意分工，不動
- `alertLogic.ts`（純判斷）vs `alerts.ts`（I/O＋訊息組裝）：`alertLogic.ts:1-3` 註解明說是為了 node --test 可直接載入而抽離純函式。**正當設計，非冗餘，保留。**
- `klineStore.ts` / `fundamentalStore.ts`（Supabase 快取表讀寫）vs `store.ts`（前端 Zustand 狀態）：命名都叫 store 但屬完全不同層（後端持久化 vs 前端記憶體狀態）。**非重複，保留。**
- `status.ts`：檔名易誤解，實為後端可觀測性（列數統計、健康彙整），與 market-hours/marketSession 無關。**非時間邏輯重複。**
