# README 重整設計

## 目標

讓第一次進入 repository 的人先看懂網站能做什麼，再依需要查閱架構、啟動、部署與安全資訊。README 必須反映目前正式環境，不保留已過時或尚未實作的功能敘述。

## 資訊順序

1. 專案名稱、一句定位與正式網站入口。
2. 核心功能，放在 README 最前段並作為視覺重點。
3. 運作架構，說明 Cloudflare、Zeabur、Supabase、TWSE 與 FinMind 的關係。
4. 本機快速啟動與雙模式儲存。
5. 環境變數、常用指令與驗收方式。
6. 自動部署設定、安全設計、資料來源與免責聲明。

## 核心功能呈現

以六個短項目呈現，每項使用一致的小圖示、粗體名稱與一至兩句說明：

- 即時行情與大盤
- 自選股管理
- 個股圖表與基本面
- 站內收盤總覽
- 到價與 LINE 提醒
- 手機 PWA 與離線體驗

功能說明只寫已實作內容，移除不存在的密度切換與尚未實作的 Web Push 計畫。

## 視覺原則

- 使用少量 emoji 作為段落識別，不使用大量動態徽章。
- 以短段落、表格與程式碼區塊控制閱讀密度。
- 使用 Mermaid 流程圖呈現部署架構，讓資料流與責任邊界一眼可辨。
- 正式網站採醒目的文字連結；Cloudflare 標示為主要入口，Zeabur 標示為後端與備援入口。
- 中文與英文、數字之間保留半形空格，全篇使用繁體中文。

## 內容校正

- 主要網址更新為 `https://twstock.xiehnet.com`。
- 補入站內收盤總覽、名稱搜尋、Toast 回饋與目前 PWA／離線能力。
- 移除過時的上層 Build Plan 連結、重複指令與重複部署說明。
- 環境變數以目前程式實際讀取者為主，不揭露任何 secret 值。
- 說清楚 GitHub `main` 同時觸發 Cloudflare 前端與 Zeabur 後端部署。

## 驗收

- README 內網址、指令、路徑與環境變數可由現有程式碼核對。
- Markdown 標題層級、表格與程式碼區塊完整。
- `npm test`、根目錄 `npm run build`、`frontend` 的 `npm run build` 皆通過。
- 變更只包含文件，不改動產品程式碼或部署設定。
