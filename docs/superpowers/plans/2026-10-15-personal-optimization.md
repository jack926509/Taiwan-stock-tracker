## 分段實作

1. B1：先寫提醒儲存層與 API 回歸測試，再修正只重設有改動的條件，增加單項重新啟用操作。保留既有到價一次性、漲跌幅／爆量每日一次語意。
2. B2：保存獨立觸發事件及通知結果；既有條件與可信行情契約保持一致。通知採固定重試識別及有上限的重試，不把 HTTP 接受當作使用者已收到或讀取。
3. B3：將後端實際檢查結果呈現在提醒頁，移除由前端行情直接推定後端暫停的文案；加入門檻距離排序。
4. C1–C2：沿用 `watchlist.group_name`，建立可操作的分組與瀏覽器偏好保存；不新增多人帳號或會員系統。
5. C3–C4：沿用既有收盤摘要邏輯保存可查日期的回顧，補上今日重點、簡單狀態及匯出。
6. 依上表逐項檢查程式、API、實際畫面及測試覆蓋，修正交叉審查問題，整理使用者驗收路徑。

- 每段先重現問題，再實作、測試、型別檢查與建置，提交本機工作分支。
